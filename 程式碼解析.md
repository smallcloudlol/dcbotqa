## 2. bot.py — 進入點

```python
EXTENSIONS = ("cogs.quiz", "cogs.leaderboard", "cogs.admin")
```

**解析：** 要載入的三個 Cog 模組。Cog 是 discord.py 把指令分組的方式，每個模組底部都有 `async def setup(bot)` 供載入時呼叫。

```python
class QuizBot(commands.Bot):
    def __init__(self):
        # 只使用斜線指令與按鈕，不需要任何 Privileged Intent
        super().__init__(command_prefix=commands.when_mentioned, intents=discord.Intents.default())
        self.db = Database(config.DB_PATH)
        self.bank = QuestionBank(config.QUESTIONS_PATH)
```

**解析：**
- 繼承 `commands.Bot`。`Intents.default()` 不包含「讀取訊息內容」等特權權限，因為本 Bot 全部走斜線指令與按鈕，不需要讀訊息，所以不用到開發者後台開啟 Privileged Intent。
- `command_prefix=commands.when_mentioned`：`commands.Bot` 一定要給前綴，這裡設成「提及 Bot」，實際上沒有文字指令。
- 把資料庫 `self.db` 和題庫 `self.bank` 掛在 Bot 上，所有 Cog 都透過 `self.bot.db`、`self.bot.bank` 共用同一份。

```python
    async def setup_hook(self):
        for extension in EXTENSIONS:
            await self.load_extension(extension)
        self.tree.error(self.on_app_command_error)

        if config.GUILD_ID:
            guild = discord.Object(id=config.GUILD_ID)
            self.tree.copy_global_to(guild=guild)
            synced = await self.tree.sync(guild=guild)
        else:
            synced = await self.tree.sync()
        log.info("已同步 %d 個斜線指令，題庫共 %d 題", len(synced), len(self.bank.questions))
```

**解析：** `setup_hook` 會在 Bot 登入後、連上 Gateway 前執行一次。
1. 依序載入三個 Cog。
2. 把 `on_app_command_error` 註冊為所有斜線指令的錯誤處理器。
3. 同步斜線指令到 Discord：
   - 有 `GUILD_ID`：把全域指令複製到該伺服器再同步，**立即生效**，適合開發。
   - 沒有：全域同步，Discord 端可能要一段時間才會出現。

```python
    async def on_app_command_error(self, interaction: discord.Interaction, error: app_commands.AppCommandError):
        if isinstance(error, app_commands.CheckFailure):
            message = "你沒有權限使用這個指令。"
        else:
            log.error("指令執行失敗", exc_info=error)
            message = "發生錯誤，請稍後再試。"
        try:
            if interaction.response.is_done():
                await interaction.followup.send(message, ephemeral=True)
            else:
                await interaction.response.send_message(message, ephemeral=True)
        except discord.HTTPException:
            pass
```

**解析：** 全域錯誤處理。
- `CheckFailure`：權限檢查沒過（例如一般成員用管理員指令）。
- 其他錯誤：寫入 log，對使用者只顯示通用訊息。
- 一個互動只能 `response` 一次，所以先用 `is_done()` 判斷：已回應過就改用 `followup`。`ephemeral=True` 表示只有本人看得到。
- 最外層吞掉 `HTTPException`，避免「回報錯誤時又出錯」。

```python
    async def close(self):
        await super().close()
        self.db.close()


def main():
    if not config.TOKEN:
        raise SystemExit("請先在 .env 設定 DISCORD_TOKEN（可參考 .env.example）")
    discord.utils.setup_logging(root=True)
    QuizBot().run(config.TOKEN, log_handler=None)
```

**解析：**
- `close()`：Bot 關閉時一併關閉 SQLite 連線。
- `main()`：沒 Token 就直接結束並提示；`setup_logging(root=True)` 讓整個程式（包含 `quizbot` logger）都使用 discord.py 的彩色 log 格式；`log_handler=None` 避免 `run()` 再重複設定一次 log。

## 3. quizbot/questions.py — 題庫

```python
MIN_OPTIONS = 2
MAX_OPTIONS = 5  # Discord 一列最多放 5 個按鈕


@dataclass(frozen=True)
class Question:
    id: str
    category: str
    difficulty: str
    question: str
    options: Tuple[str, ...]
    answer: int  # 正確選項的索引（從 0 開始）
    explanation: str = ""
```

**解析：**
- 選項數限制 2～5：作答按鈕 A～E 放在同一列，而 Discord 一列最多 5 個按鈕。
- `Question` 用 `frozen=True` 的 dataclass，建立後不可修改，避免題目在執行中被誤改。
- `options` 用 tuple（不可變），`answer` 是 **從 0 開始的索引**（0 = A、1 = B…）。

```python
def parse_question(item: Dict[str, Any]) -> Question:
    question = Question(
        id=str(item["id"]),
        category=str(item["category"]).strip(),
        difficulty=str(item.get("difficulty", "medium")),
        question=str(item["question"]).strip(),
        options=tuple(str(option) for option in item["options"]),
        answer=int(item["answer"]),
        explanation=str(item.get("explanation", "")),
    )
```

**解析：** 把 JSON 裡的一題（dict）轉成 `Question`。必填欄位用 `item["..."]`（缺少會拋 `KeyError`），選填欄位用 `.get()` 給預設值（難度預設 medium、解析預設空字串）。全部用 `str()`／`int()` 轉型，就算 JSON 寫成數字也能正常處理。

```python
    if not question.question or not question.category:
        raise ValueError(f"題目 {question.id}：question 與 category 不可為空")
    if not MIN_OPTIONS <= len(question.options) <= MAX_OPTIONS:
        raise ValueError(f"題目 {question.id}：選項數量需介於 {MIN_OPTIONS}～{MAX_OPTIONS}")
    if not 0 <= question.answer < len(question.options):
        raise ValueError(f"題目 {question.id}：answer 需為選項索引 0～{len(question.options) - 1}")
    if question.difficulty not in BASE_POINTS:
        raise ValueError(f"題目 {question.id}：difficulty 需為 {' / '.join(BASE_POINTS)}")
    return question
```

**解析：** 四項驗證，錯誤訊息都帶題目 id，方便找出哪一題寫錯：
1. 題目與分類不可空白
2. 選項數量 2～5
3. `answer` 必須是合法索引（例如 4 個選項只能是 0～3）
4. 難度必須是 `scoring.BASE_POINTS` 的 key（easy / medium / hard），計分規則與驗證共用同一份資料。

```python
class QuestionBank:
    def __init__(self, path: str):
        self.path = path
        self.questions: List[Question] = []
        self.reload()

    def reload(self) -> int:
        """重新讀取題庫。檔案有誤時會拋出例外，並保留原本的題目。"""
        with open(self.path, encoding="utf-8") as file:
            raw = json.load(file)
        questions = [parse_question(item) for item in raw]
        if not questions:
            raise ValueError("題庫是空的")
        seen = set()
        for question in questions:
            if question.id in seen:
                raise ValueError(f"題目 id 重複：{question.id}")
            seen.add(question.id)
        self.questions = questions
        return len(questions)
```

**解析：** 題庫載入。關鍵在於**先把全部題目解析到區域變數 `questions`，所有檢查（非空、id 不重複）都通過後，最後一行才替換 `self.questions`**。只要中途任何一題出錯就會拋例外、不會執行到替換，所以舊題庫完整保留。`/reload_questions` 就是靠這個特性做到「熱更新失敗也不影響運作」。

```python
    def categories(self) -> List[str]:
        return list(dict.fromkeys(question.category for question in self.questions))
```

**解析：** 取得所有分類。`dict.fromkeys` 會去除重複，而且和 `set` 不同，**會保留第一次出現的順序**，所以分類順序和題庫檔一致。

```python
    def random(self, category: Optional[str] = None, exclude: Iterable[str] = ()) -> Optional[Question]:
        """隨機抽一題，盡量避開 exclude 中最近答過的題目。"""
        pool = [q for q in self.questions if category is None or q.category == category]
        excluded = set(exclude)
        candidates = [q for q in pool if q.id not in excluded] or pool
        return random.choice(candidates) if candidates else None
```

**解析：**
1. `pool`：沒指定分類就是全部題目，否則只取該分類。
2. `candidates`：再排除最近答過的題目。
3. `or pool`：如果排除後一題都不剩（例如某分類只有 4 題、使用者都答過了），就退回整個 `pool`，**寧可重複也不要抽不到題**。
4. 真的沒題目時回傳 `None`。

## 4. quizbot/scoring.py — 計分

```python
BASE_POINTS = {"easy": 10, "medium": 20, "hard": 30}
SPEED_BONUS_RATIO = 0.5  # 立刻作答最多再加基本分的 50%
STREAK_BONUS_STEP = 5
STREAK_BONUS_MAX = 25


@dataclass(frozen=True)
class ScoreResult:
    points: int
    base: int
    speed_bonus: int
    streak_bonus: int
```

**解析：** 計分參數集中在檔案開頭，要調整規則只改這裡；`/help` 的說明文字也直接引用這些常數，會自動同步。`ScoreResult` 除了總分 `points` 也保留各項明細，讓結果畫面能顯示「基本 20 ＋ 速度 9 ＋ 連對 15」。

```python
def calculate_score(correct: bool, difficulty: str, elapsed: float, time_limit: float, streak: int) -> ScoreResult:
    """計算單題得分。streak 為「含本題」的連續答對題數。"""
    if not correct:
        return ScoreResult(0, 0, 0, 0)
    base = BASE_POINTS.get(difficulty, BASE_POINTS["medium"])
```

**解析：** 答錯或逾時直接 0 分。基本分依難度取得，萬一難度不存在就當 medium（實際上 `parse_question` 已經擋掉了，這是雙重保險）。

```python
    remaining = min(max(time_limit - elapsed, 0.0), time_limit) / time_limit if time_limit > 0 else 0.0
    speed_bonus = int(base * SPEED_BONUS_RATIO * remaining + 0.5)  # 四捨五入（round() 是銀行家捨入）
```

**解析：** 速度加成。
- `remaining`：剩餘時間比例，限制在 0～1 之間（`time_limit` 為 0 時避免除以零）。
- 加成 = 基本分 × 0.5 × 剩餘比例，所以越快答越多，最多是基本分的一半。
- 用 `int(x + 0.5)` 做四捨五入：Python 的 `round(2.5)` 會得到 2（銀行家捨入，取偶數），不符合一般人直覺，所以自己實作。

```python
    streak_bonus = min(max(streak - 1, 0) * STREAK_BONUS_STEP, STREAK_BONUS_MAX)
    return ScoreResult(base + speed_bonus + streak_bonus, base, speed_bonus, streak_bonus)
```

**解析：** 連對加成 = (連對數 − 1) × 5，上限 25。第 1 題答對沒有加成、第 2 題 +5、第 3 題 +10…第 6 題起固定 +25。

**計算範例：** 中等題（20 分）、限時 30 秒、第 3 秒答對、這是連續第 4 題答對
→ 速度 `20 × 0.5 × 27/30 = 9`，連對 `(4−1) × 5 = 15`，**總分 20 + 9 + 15 = 44**。

## 5. quizbot/database.py — 資料庫

```sql
CREATE TABLE IF NOT EXISTS users (
    guild_id    INTEGER NOT NULL,
    user_id     INTEGER NOT NULL,
    username    TEXT    NOT NULL,
    score       INTEGER NOT NULL DEFAULT 0,
    answered    INTEGER NOT NULL DEFAULT 0,
    correct     INTEGER NOT NULL DEFAULT 0,
    streak      INTEGER NOT NULL DEFAULT 0,
    best_streak INTEGER NOT NULL DEFAULT 0,
    PRIMARY KEY (guild_id, user_id)
);
```

**解析：** 使用者累計資料表。主鍵是 `(guild_id, user_id)` 的組合，所以**同一個人在不同伺服器的分數是分開的**。欄位：總分、答題數、答對數、目前連對、最高連對。

```sql
CREATE TABLE IF NOT EXISTS answers (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,
    guild_id    INTEGER NOT NULL,
    user_id     INTEGER NOT NULL,
    question_id TEXT    NOT NULL,
    category    TEXT    NOT NULL,
    mode        TEXT    NOT NULL,          -- quiz / challenge
    chosen      INTEGER,                   -- NULL 代表逾時未作答
    correct     INTEGER NOT NULL,
    elapsed     REAL,
    points      INTEGER NOT NULL,
    answered_at TEXT    NOT NULL DEFAULT (datetime('now'))
);

CREATE INDEX IF NOT EXISTS idx_users_score ON users (guild_id, score DESC);
CREATE INDEX IF NOT EXISTS idx_answers_user ON answers (guild_id, user_id);
```

**解析：** 每一次作答的明細表，用於分類統計、避開重複題、匯出 CSV。
- `category` 在作答時一併存下來，即使之後題庫修改了分類，歷史紀錄仍正確。
- `answered_at` 用 SQLite 的 `datetime('now')`，時間為 **UTC**。
- 兩個索引分別加速排行榜排序與查詢個人紀錄。
- 全部用 `IF NOT EXISTS`，每次啟動都執行也不會出錯。

```python
@dataclass
class UserStats:
    user_id: int
    username: str
    score: int
    answered: int
    correct: int
    streak: int
    best_streak: int

    @property
    def accuracy(self) -> float:
        return self.correct / self.answered if self.answered else 0.0
```

**解析：** 對應 `users` 一列資料。正確率用 `@property` 即時計算，不另外存；答題數為 0 時回傳 0，避免除以零。`CategoryStats` 是同樣的設計，用在各分類統計。

```python
USER_COLUMNS = "user_id, username, score, answered, correct, streak, best_streak"


class Database:
    def __init__(self, path: str):
        if path != ":memory:" and os.path.dirname(path):
            os.makedirs(os.path.dirname(path), exist_ok=True)
        self._conn = sqlite3.connect(path)
        self._conn.row_factory = sqlite3.Row
        self._conn.executescript(SCHEMA)
```

**解析：**
- `USER_COLUMNS` 的順序與 `UserStats` 欄位一致，查詢結果可以直接 `UserStats(**dict(row))`。
- 資料夾不存在就自動建立；`:memory:` 是記憶體資料庫（測試用），不需要建資料夾。
- `row_factory = sqlite3.Row` 讓查詢結果可以用欄位名稱存取（`row["score"]`）。
- `executescript(SCHEMA)` 建立資料表。

```python
    def get_user(self, guild_id: int, user_id: int) -> Optional[UserStats]:
        row = self._conn.execute(
            f"SELECT {USER_COLUMNS} FROM users WHERE guild_id = ? AND user_id = ?",
            (guild_id, user_id),
        ).fetchone()
        return UserStats(**dict(row)) if row else None
```

**解析：** 查詢單一使用者，沒有紀錄回傳 `None`。f-string 只拼接固定的欄位名稱常數，實際的值都用 `?` 參數化，**不會有 SQL Injection 風險**。

```python
    def record_answer(self, *, guild_id, user_id, username, question_id, category, mode,
                      chosen, correct, elapsed, points) -> UserStats:
        with self._conn:
            self._conn.execute(
                """INSERT INTO users (guild_id, user_id, username) VALUES (?, ?, ?)
                   ON CONFLICT (guild_id, user_id) DO UPDATE SET username = excluded.username""",
                (guild_id, user_id, username),
            )
```

**解析：** 寫入一次作答（參數前的 `*` 強制呼叫時必須寫參數名稱，避免順序搞錯）。
- `with self._conn:` 開啟交易：區塊內全部成功才 commit，任何一步失敗就 rollback。
- 第一步是 **Upsert**：使用者不存在就新增；已存在就只更新顯示名稱（使用者改暱稱時排行榜會跟著更新）。

```python
            # SQLite 的 UPDATE 右側一律讀取舊值，所以 best_streak 會用到更新前的 streak
            self._conn.execute(
                """UPDATE users SET
                       score = score + :points,
                       answered = answered + 1,
                       correct = correct + :correct,
                       streak = CASE WHEN :correct THEN streak + 1 ELSE 0 END,
                       best_streak = MAX(best_streak, CASE WHEN :correct THEN streak + 1 ELSE 0 END)
                   WHERE guild_id = :guild_id AND user_id = :user_id""",
                {"points": points, "correct": int(correct), "guild_id": guild_id, "user_id": user_id},
            )
```

**解析：** 第二步更新累計數字，全部在資料庫內計算（`score = score + :points`），不會有「讀出來 → 加 → 寫回」的競態問題。
- 答對：`streak + 1`；答錯：歸零。
- `best_streak` 這行裡的 `streak` 讀到的是**更新前的舊值**（SQL 標準：同一個 UPDATE 中 SET 右邊都讀舊值），所以要再寫一次 `streak + 1` 才是新的連對數，再與歷史最高取 `MAX`。
- 使用 `:name` 具名參數，同一個值（`:correct`）可以重複使用。

```python
            self._conn.execute(
                """INSERT INTO answers (guild_id, user_id, question_id, category, mode, chosen, correct, elapsed, points)
                   VALUES (?, ?, ?, ?, ?, ?, ?, ?, ?)""",
                (guild_id, user_id, question_id, category, mode, chosen, int(correct), elapsed, points),
            )
        stats = self.get_user(guild_id, user_id)
        assert stats is not None
        return stats
```

**解析：** 第三步寫入作答明細。三步都在同一個交易中，**分數與明細不會出現只寫一半的情況**。最後回傳更新後的使用者統計，給結果畫面使用。

```python
    def rank(self, guild_id: int, user_id: int) -> Optional[int]:
        row = self._conn.execute(
            "SELECT score FROM users WHERE guild_id = ? AND user_id = ?", (guild_id, user_id)
        ).fetchone()
        if row is None:
            return None
        higher = self._conn.execute(
            "SELECT COUNT(*) FROM users WHERE guild_id = ? AND score > ?", (guild_id, row["score"])
        ).fetchone()[0]
        return higher + 1
```

**解析：** 名次 = 分數比自己高的人數 + 1。同分的人會是同一個名次（例如兩人並列第 2，下一位是第 4）。

```python
    def leaderboard(self, guild_id: int, limit: int = 10) -> List[UserStats]:
        rows = self._conn.execute(
            f"""SELECT {USER_COLUMNS} FROM users WHERE guild_id = ?
```

```python
class QuizView(discord.ui.View):
```

- 依選項數量加入 2～5 個按鈕。


**解析：**
- `start_timer()`：題目訊息送出後才開始計時。

2. 從「進行中」集合移除，使用者才能開下一題
3. 結算並寫入資料庫


```python
DIMENSIONS = {"A": "接受程度", "B": "互動體驗", "C": "使用意願"}
LIKERT_TEXT = {"非常不同意": 1, "不同意": 2, "普通": 3, "沒意見": 3, "同意": 4, "非常同意": 5}
ITEM_HEADER = re.compile(r"^\s*([A-Za-z])(\d+)(?:\s*[.．、:：]\s*|\s+|$)(.*)$")
LIKERT_NUMBER = re.compile(r"^([1-5])(?!\d)")
```

**解析：**
- 三個構面對應題號字母 A／B／C。
- `LIKERT_TEXT`：文字選項轉分數，「普通」與「沒意見」都算 3。
- `ITEM_HEADER`：辨識題目欄位標題，例如 `A1. 題目`、`B2、題目`、`C3：題目`（支援全形與半形標點），分別擷取字母、題號、題目文字。
- `LIKERT_NUMBER`：開頭是 1～5 且後面不是數字，例如「5」「5 非常同意」會取 5，但「10」不會被誤判成 1。

```python
def parse_likert(value: Optional[str]) -> Optional[int]:
    text = (value or "").strip()
    if not text:
        return None
    if text in LIKERT_TEXT:
        return LIKERT_TEXT[text]
    match = LIKERT_NUMBER.match(text)  # 支援「5」或「5 非常同意」
    return int(match.group(1)) if match else None
```

**解析：** 把一格作答轉成 1～5 分；空白或無法辨識回傳 `None`（視為未作答）。

```python
def find_items(headers: Sequence[str]) -> Dict[str, List[Tuple[int, str, str]]]:
    """回傳 {構面代碼: [(欄位索引, 題號, 題目文字), ...]}。"""
    items: Dict[str, List[Tuple[int, str, str]]] = {letter: [] for letter in DIMENSIONS}
    for column, header in enumerate(headers):
        match = ITEM_HEADER.match(header)
        if not match:
            continue
        letter = match.group(1).upper()
        if letter in items:
            items[letter].append((column, f"{letter}{match.group(2)}", match.group(3).strip()))
    return items
```

**解析：** 掃描每個欄位標題，把符合題號格式、且字母屬於 A／B／C 的欄位歸到對應構面。時間戳記、基本資料、開放式問題因為不符合格式而自動略過。

```python
def cronbach_alpha(matrix: Sequence[Sequence[float]]) -> Optional[float]:
    """matrix 每一列是一位受訪者、每一欄是一題（只含完整作答者）。"""
    if len(matrix) < 2 or len(matrix[0]) < 2:
        return None
    k = len(matrix[0])
    item_variance = sum(statistics.variance(column) for column in zip(*matrix))
    total_variance = statistics.variance([sum(row) for row in matrix])
    if total_variance == 0:
        return None
    return k / (k - 1) * (1 - item_variance / total_variance)
```

**解析：** Cronbach's α 信度係數，公式：

$$\alpha = \frac{k}{k-1}\left(1 - \frac{\sum \sigma^2_{\text{各題}}}{\sigma^2_{\text{總分}}}\right)$$

- `zip(*matrix)` 把「每列一人」轉置成「每列一題」，計算各題變異數再加總。
- `[sum(row) for row in matrix]` 是每人的總分，再算總分變異數。
- 樣本少於 2 人、題數少於 2 題，或總分變異數為 0（大家答得一模一樣）時無法計算，回傳 `None`。

```python
def describe_alpha(alpha: Optional[float]) -> str:
    if alpha is None:
        return "資料不足"
    for threshold, label in ((0.9, "極佳"), (0.8, "良好"), (0.7, "可接受"), (0.6, "尚可")):
        if alpha >= threshold:
            return label
    return "偏低"
```

**解析：** 依常用門檻把 α 轉成文字評語，由高到低比對，符合第一個就回傳。

```python
    parser = argparse.ArgumentParser(description="分析問卷回覆 CSV")
    parser.add_argument("csv_path", help="問卷回覆 CSV 檔")
    parser.add_argument("-o", "--output", help="輸出 Markdown 報告的路徑（未指定則印在畫面上）")
    args = parser.parse_args(argv)

    with open(args.csv_path, encoding="utf-8-sig", newline="") as file:
        reader = csv.reader(file)
        headers = next(reader, [])
        rows = [row for row in reader if any(value.strip() for value in row)]

    report = analyze(headers, rows)
    if args.output:
        with open(args.output, "w", encoding="utf-8") as file:
            file.write(report)
        print(f"已輸出報告：{args.output}")
    else:
        if hasattr(sys.stdout, "reconfigure"):
            sys.stdout.reconfigure(errors="replace")
        print(report)
```

**解析：**
- `argparse` 處理命令列參數；`argv` 參數讓測試時可以直接傳入參數清單。
- 用 `utf-8-sig` 讀檔，不論 CSV 有沒有 BOM 都能正確讀取；`newline=""` 是 `csv` 模組要求的寫法，避免欄位內換行出錯。
- 第一列是標題，之後略過整列空白的資料列。
- 有 `-o` 就寫檔，否則印到畫面；Windows 命令列編碼可能無法顯示某些字元，`errors="replace"` 讓它以替代字元顯示而不是當掉。

## 11. 限制與可改進之處

| # | 現況 | 影響 | 建議 |
|---|---|---|---|
| 1 | View 不是 persistent view，進行中狀態存在記憶體 | Bot 重啟後舊按鈕會顯示「互動失敗」，進行中的題目不會結算 | 使用量小可接受；需要時改用 persistent view |
| 2 | `sqlite3` 為同步呼叫，在 event loop 中直接執行 | 大量同時作答時會短暫阻塞 | 改用 `aiosqlite` 或 `asyncio.to_thread` |
| 3 | `/challenge` 抽題沒有避開最近出過的題目 | 同一頻道可能連續出到重複題 | 記錄頻道最近題號並傳入 `exclude` |
| 4 | `/challenge` 沒檢查 `bank.random()` 回傳 `None` | 目前題庫保證非空，實際不會發生 | 比照 `/quiz` 加防呆 |
| 5 | 挑戰模式沒作答的人不留紀錄、不中斷連對；個人模式逾時會中斷連對 | 兩種模式規則不一致（屬設計取捨） | 視需求決定是否統一 |
| 6 | 連對數在 `/quiz` 與 `/challenge` 間共用 | 挑戰答錯會中斷個人連對 | 需要時可依模式分開記錄 |
| 7 | `rank()` 只比分數，`leaderboard()` 還比答對數 | 同分時排行榜順序與 `/stats` 名次看起來不一致 | `rank()` 使用相同排序條件 |
| 8 | 沒有自動化測試 | 修改計分或資料庫時較難確認正確 | `quizbot/` 不依賴 Discord，可用 `pytest` + `Database(":memory:")` 補測試 |
